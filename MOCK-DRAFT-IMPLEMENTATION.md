# Mock draft implementation

Existing sources: `repository.js` league/season JSON and atomic writes; `standings-service.js` official regular-season records; `roster-service.js` memberships; `role-ownership.js` and owners.json coach identities; `trade-service.js` draft-picks.json ownership; `scouting-service.js` current CUS Big Board and portraits; `discord-channels.js` Scouting Hub/settings; `discord-permissions.js` staff authorization. No website changes.

1. Central draft-order service: season-selected lottery rules, original pick identities, ownership, stable record ties, seeding projection and optional play-in results/history settings.
2. Shared CPU engine: bounded weighted value/need/quality/fit/market selection with seeded testing and prior selections.
3. Saved simulation snapshots: 1,000 complete first rounds, aggregates and metadata; durable post-commit refresh requests; validate before atomic replacement.
4. Private `/mockdraft` projection and persistent pinned Scouting Hub entry.
5. Persisted live state machine, private threads, configured coach invites, lottery/lock/start, timestamp clocks, atomic selection, pause/resume.
6. Varied graded reactions, full recap, participant DM delivery records, recoverable cleanup and Discord outbox.
7. Automated engine, lifecycle, concurrency, refresh and Discord tests; full npm check.

NBA source: https://www.nba.com/news/nba-board-governors-approve-new-draft-lottery-system (May 28, 2026). 2027–2029 use 3-2-1, all 16 slots drawn, bottom-three floor #12 and original-team repeat restrictions. User requests continued 3-2-1 for 2030+; label that as a provisional continuation until NBA announces rules. No real playoff execution is added. `settings.mockDraft.playInLoserTeamIds` can provide the actual 7/8 losers; otherwise project the eighth seed losing. `priorOriginalPicks` supplies prior real draft slots for repeat restrictions; never use past mock results as real draft history. Missing history is explicitly disclosed. Tie drawings are represented by a season-specific stable hash, independent of traded ownership.

Live presentation: lottery runs post all 30 slots in one embed with current-owner team emojis and traded-pick labels. View Current Order privately redisplays the saved lottery or locked order without drawing again. Recovery upgrades the current run’s older three-page display. Best-available/search views feature the first displayed prospect’s existing portrait; pick previews, reactions, and recap pages also use existing portraits when available.

Turn delivery: each human-controlled pick posts a coach-addressed Make Pick prompt in the live room after the previous pick reaction. Only the coach on the clock can open its ephemeral selection panel. Pausing disables the prompt; advancing clears old buttons. Delivery markers prevent duplicate prompts after recovery. No turn DMs are sent. The draft room and participant DMs share the same final recap embed containing all 30 picks, grades, team emojis and takeaways, without portraits.

Before drawing, View Base Order displays the 30-slot standings-based order, with pick ownership. The host/staff can Use This Order and lock it without a lottery; a subsequent lottery replaces it before lock. Selection validates the current order revision, class and host authority.

Engine version 2 uses board rank as the talent anchor, with bounded factors for positional depth and starter overall, aging-starter succession, complementary shooting/playmaking/defense/rim skills, three-point rating and rotation spacing, prospect age, immediate readiness and upside. Contenders emphasize readiness while weaker rosters give youth/upside more weight. All three strengths and roster archetypes contribute; missing ratings stay neutral, with shooting archetypes used as a modest proxy. Age uses the draft-season reference date, not wall-clock time. Earlier picks become roster depth and reduce redundant needs. The same engine drives saved simulations and live CPU picks. An engine version change refreshes simulations without old-version market feedback. Published weekly command projections remain frozen until the next week.

Live lotteries use fresh cryptographic random draws. Persisted order fingerprints reject previously displayed orders in that mock, with bounded redraws and the prior order retained if a distinct valid draw cannot be found. Base preview and selected-order panels include Start Draft; the host/staff action locks the chosen order and begins immediately.

Recap reliability: message nonces include the destination channel ID so a room recap cannot collide with its identical DM. Temporary DM failures retry up to three times before cleanup; permanently closed DMs are recorded without blocking other recipients. Recovery also retries failed archived recaps. Grades place more weight on market value and reach cost, while labels recognize shooting, upside, readiness and defensive contribution; Luxury pick requires low need, low fit, limited upside and little spacing contribution. Repeated eligible labels receive a bounded preference penalty.

Engine version 3 applies a strict reach window to live CPU picks, timeout picks, regular projections and all saved simulation rounds: 2 board places for picks 1–5, 3 for 6–14, and 5 for 15–30. Candidates must fit both the current pick and best available board rank; if earlier coach picks depleted that range, the best remaining prospect remains eligible. Fit factors and random weights operate within that pool. Coach choices remain available through the existing selection UI. A version upgrade refreshes the published regular projection once, then preserves its usual weekly stability.
